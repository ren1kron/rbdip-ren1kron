# Миграции

`V1__init.sql` — начальная схема, эталон, не редактируется.

Свои миграции добавляйте следующими номерами: `V2__...sql`, `V3__...sql` и т.д.
(стандартная схема именования Flyway: `V<версия>__<описание>.sql`).

## Конвенции, на которые опираются эталонные тесты

**ЛР2 (нормализация).** Данные клиента переезжают в таблицу `customers`, имя клиента —
в колонку `customers.full_name`. Из `orders` уходят `customer_full_name`,
`customer_address`, `customer_phone`, из `order_items` — `product_name`, `product_price`.

**ЛР3 (expand-contract).** Разбиение `customers.full_name` на `first_name`/`last_name`:

- в описании каждой миграции ЛР3 есть `lab3`, например
  `V7__lab3_expand_add_name_columns.sql`, `V8__lab3_backfill_names.sql`,
  `V9__lab3_contract_drop_full_name.sql`;
- миграций ЛР3 не меньше двух, все они идут после миграций ЛР2;
- последняя миграция в цепочке — contract-шаг (удаление `full_name`); все предыдущие
  шаги ЛР3 не должны ломать чтение `full_name` и должны заполнить новые колонки
  для уже существующих клиентов.

## Выкладка ЛР3 без остановки API

Версия `79198fd` работает с нормализованной схемой V2 и читает `full_name`. Начиная с `fa994d1` приложение читает раздельные поля и может обслуживать запросы на схемах V4 и V5.

1. На узлах, обслуживающих HTTP, задайте `SPRING_FLYWAY_ENABLED=false`. Для отдельного процесса миграции используйте итоговый JAR и те же `SPRING_DATASOURCE_URL`, `SPRING_DATASOURCE_USERNAME` и `SPRING_DATASOURCE_PASSWORD`, что у приложения.
2. Пока версия V2 принимает заказы, выполните команду ниже с целью V4. При тайм-ауте блокировки V3 (2 секунды) дождитесь завершения долгих транзакций и повторите запуск с целью V4. V3 включает двустороннюю запись, V4 заполняет имена старых клиентов. Межсловный пробел разделяет имя и фамилию, остальные пробелы сохраняются. Для имени из одного слова фамилия пустая.
3. Выпустите приложение с чтением новых полей. Проверьте создание и выдачу заказов, дождитесь завершения запросов на старых узлах и переключите фоновых потребителей старого поля. До V5 можно вернуть приложение версии V2.
4. Запустите ту же команду с `--spring.flyway.target=5`. При тайм-ауте блокировки транзакция откатится. Повторите команду после завершения долгих транзакций. После V5 для отката приложения используйте версию с чтением раздельных полей.

```sh
java -jar target/bookstore-0.1.0.jar --spring.main.web-application-type=none \
  --spring.flyway.enabled=true --spring.flyway.target=4
```

На новой базе обычный запуск приложения автоматически применяет всю цепочку.
